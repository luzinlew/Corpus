# Цикл задачи (ведёт координатор)

0. Осмотр и возобновление. Прочитай шапку и очередь `.claude/TASKS.md`, затем `git status --short`, `git branch --show-current`, `git log --oneline -5`.
   - Есть задача in-progress/review → продолжи с её поля «шаг». Ветка должна совпадать, незакоммиченное — только файлы из её поля «файлы». Иначе спроси Льва.
   - Дерево грязное, а активной задачи нет → стоп, спроси.
1. Выбор: верхняя planned без пометки «решение Льва». Одна задача за запуск.
2. План (сам): цель; файлы и места (Grep, номера строк); проверка, которая докажет поведение; риски (claude.ai, гость, createdAt, три языка); нужен ли SQL/функция и их откат. Запиши в журнал.
   Дифф > 300 строк (без index.html), схема/RLS/auth или продуктовое решение → покажи план Льву, жди «да».
3. Ветка: `git switch -c claude/T-xxx-<slug> main` (или существующая ветка задачи).
4. Реализация: implementer, план целиком, с номерами строк.
5. Проверка: qa-quick. FAIL → implementer со строками FAIL (попытка 2). Снова FAIL → разбери сам; третья неудача → blocked, стоп.
6. Ревью (только нужные, одновременно):
   - qa-review — >30 строк логики в src/corpus.html или web.js; импорт/экспорт/createdAt/синхронизация; изменены тесты.
   - security-reviewer — web.js, sw.js, supabase/**, вход, обмен, ИИ-запросы, innerHTML с чужими данными.
   - ESCALATE или high/critical → разбери сам; не уверен → вопрос Льву, задача blocked.
   - Исправления → implementer → qa-quick, в пределах бюджета попыток.
7. Коммит (сам): `git add` только файлов задачи, сообщение по-русски в стиле истории; `git push -u origin claude/T-xxx-<slug>`. Обнови журнал, закоммить и запушь его в ту же ветку.
8. Итог Льву (≤ 15 строк): что сделано; доказательства проверок; находки ревью и что с ними; SQL/код функции и их откат целиком; что нужно от Льва. Деплой не выполнять.

Стоп и вопрос Льву: нужно менять прод Supabase; тест падает и на main; хочется ослабить проверку или тест; нужно решение о продукте; бюджет из шапки TASKS.md исчерпан.
